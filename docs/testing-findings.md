# Backend testing findings

These findings describe the current canonical implementation. Coverage work does not change production behavior.
`CONFIRMED` means a deterministic test marked `bug` reproduces the problem. `OPEN` means the behavior is
documented but needs a product decision or a production testability change.

| ID | Severity | Type | Area | Summary | Reproduction/Test | Observed | Expected | Status |
|---|---|---|---|---|---|---|---|---|
| ND-BE-001 | Critical | SECURITY_CONCERN | Cart | Cart endpoints use `AllowAny` and caller-supplied user IDs. | `test_current_security_defect_allows_anonymous_client_to_manage_victim_cart` | An anonymous caller creates, reads, updates, and deletes a victim's cart when the victim ID is known. | Cart mutations must require authentication and derive or authorize ownership. | CONFIRMED |
| ND-BE-002 | Critical | SECURITY_CONCERN | Orders | Order creation and history use `AllowAny` and caller-supplied user IDs. | `test_current_security_defect_allows_anonymous_order_for_victim_and_consumes_victim_cart`, `test_current_security_defect_allows_anonymous_client_to_read_victim_order_history` | An anonymous caller can read a victim's order history, create an order for that victim, and consume the victim's cart. | Order reads and creation must require authentication and authorize the target user/cart. | CONFIRMED |
| ND-BE-003 | Major | DEFECT_CANDIDATE | Password reset | The POST view shadows the imported token-reset serializer with an email-only serializer. | `test_current_reset_password_defect_rejects_documented_token_payload` | The documented `uid`/`token`/`new_password` payload is rejected and the password remains unchanged. | The documented valid token payload resets the password. | CONFIRMED |
| ND-BE-004 | Major | DEFECT_CANDIDATE | Password reset | The token-reset serializer declares `access_token` but reads `attrs['token']`. | `test_current_reset_serializer_defect_reads_undeclared_token_field` | A structurally valid serializer payload raises `KeyError('token')`. | Validation must use one consistently declared token field and return controlled validation errors. | CONFIRMED |
| ND-BE-005 | Major | DEFECT_CANDIDATE | Registration | Activation-email failure occurs after account persistence. | `test_current_registration_defect_persists_inactive_user_after_email_failure` | The endpoint returns 500 but leaves an inactive account; a retry encounters duplicate email. | Registration should be atomic or provide a defined recoverable retry path. | CONFIRMED |
| ND-BE-006 | Major | DEFECT_CANDIDATE | Product pagination | `limit > 100` writes to DRF's read-only `request.query_params`. | `test_current_pagination_defect_returns_500_when_limit_exceeds_cap` | A large limit returns HTTP 500. | The limit should be capped or rejected with a controlled 4xx response. | CONFIRMED |
| ND-BE-007 | Major | DEFECT_CANDIDATE | Categories | Create requires client-supplied server-managed fields. | `TestCategoryViews.test_current_category_create_defect_rejects_documented_payload` | The documented create payload returns 400 for missing `id`, `creationAt`, and `updatedAt`. | The documented payload should create a category without server-generated fields. | CONFIRMED |
| ND-BE-008 | Major | SECURITY_CONCERN | Product images | Upload, reorder, and delete endpoints use `AllowAny`. | `test_current_security_defect_allows_anonymous_product_image_upload`, `test_current_security_defect_allows_anonymous_product_image_reorder`, `test_current_security_defect_allows_anonymous_product_image_delete` | Anonymous callers can mutate product images. | Image mutations must require an authorized actor. | CONFIRMED |
| ND-BE-009 | Major | AMBIGUOUS_CONTRACT | Cart quantities | Zero and quantities greater than stock are accepted. | `test_cart_currently_allows_zero_and_over_stock_quantities` | Both values are persisted. | Requires product/requirements clarification. | OPEN |
| ND-BE-010 | Major | TESTABILITY_LIMITATION | Checkout | Calculation, cart consumption, and persistence are embedded in the API view. | `tests/api/test_orders_payments_api.py` and source inspection | There is no atomic service boundary for focused business-logic tests. | Introduce a service/transaction boundary when production changes are permitted. | OPEN |
| ND-BE-011 | Major | MISSING_REQUIREMENT | Orders | Checkout does not create `OrderItem` price/quantity snapshots. | `test_current_security_defect_allows_anonymous_order_for_victim_and_consumes_victim_cart` plus source inspection | Only the product M2M relation and aggregate total are retained. | Requires product/requirements clarification for historical order snapshots. | OPEN |
| ND-BE-012 | Major | MISSING_REQUIREMENT | Discounts | No explicit 0–100 validation or canonical discounted-price calculation exists. | `test_product_serializer_currently_accepts_out_of_range_discount` | Negative and greater-than-100 values pass validation and persist. | Requires product/requirements clarification. | OPEN |
| ND-BE-013 | Minor | AMBIGUOUS_CONTRACT | Image deletion | Metadata deletion continues after storage cleanup fails. | `test_ambiguous_current_behavior_deletes_image_metadata_when_storage_cleanup_fails` | HTTP 204 is returned and metadata is removed, potentially orphaning stored objects. | Requires product/requirements clarification. | OPEN |
| ND-BE-014 | Minor | TESTABILITY_LIMITATION | User routing | URLs mix `users.interfaces...` and `src.users.interfaces...` imports. | `users/interfaces/urls.py` and isolated resend-email failure test | The same source can load under two module identities, complicating patching and process state. | Use one canonical import namespace when production changes are permitted. | OPEN |
| ND-BE-015 | Minor | TESTABILITY_LIMITATION | Storage | The production storage class hard-codes bucket/CDN identity and has no local endpoint seam. | `src/s3.py` inspection | Safe adapter integration testing cannot be configured locally. | Make storage identity/endpoint injectable when production changes are permitted. | OPEN |
| ND-BE-016 | Major | DEFECT_CANDIDATE | Image reorder | Multi-image reorder is not atomic. | `test_current_reorder_atomicity_defect_persists_earlier_update_before_later_validation_failure` | An early valid image update persists before a later foreign image causes HTTP 400. | A rejected reorder must leave every image unchanged. | CONFIRMED |
